# Authority transfers per output, not per process

`oblisk-supervisor-services-dbus.md` §15.4 framed promotion as one atomic event gated on presentation evidence from every connected display. A single sleeping (DPMS-off) or slow-to-wake output would then stall promotion everywhere, or force an arbitrary global deadline to choose between leaking the old generation forever or blind-promoting the candidate onto an output it never actually proved it could paint: the exact black-frame failure PBA exists to prevent. We split authority into a per-(generation, output) relationship instead of a per-generation flag: each output transfers to the candidate independently, the moment its own presentation evidence lands, with no barrier on its siblings. The Supervisor reaps a generation once it owns zero outputs, which can happen immediately or minutes later if one output stays asleep.

This is also just a better fit for the existing model: a `surface` with `monitor = "All"` already binds one distinct `wl_surface` per output, so per-output authority matches how the surfaces are actually bound rather than imposing a whole-process abstraction on top of it.

Considered keeping authority whole-process with a deadline that force-promotes every output, including a stalled one, once the deadline passes. Rejected: promoting onto an output that never proved it could paint reintroduces the black-frame risk PBA is supposed to eliminate. The two failure modes need separate handling regardless: a dead candidate process (SIGCHLD before any output promotes) aborts the whole candidate, full stop. A merely-slow output on a live candidate just waits, indefinitely if needed, with the candidate's null-buffer already staged there.
